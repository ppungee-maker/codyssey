# B1-3 실행 가이드 (현행화 — 2026.07.20)

> Make 시나리오는 **이미 구축 완료**. 이 문서는 남은 작업만 다룹니다.

---

## 확정된 워크플로우

```
[Trigger]  Google Sheets — Watch New Rows (참석 응답 시트)
    |
[Router]   참석 여부 판정
    |
    +-- 1st: 참석 확정 --> [Action 1] Gmail 발송 (참석 안내)
    |                      [Action 2] Sheets '참석자' 시트 기록
    |
    +-- 2nd: 미참석   --> [Action 1] Gmail 발송 (미참석 확인)
                          [Action 2] Sheets '미참석자' 시트 기록
```

| 요구사항 | 상태 |
|---|---|
| Trigger 1개 이상 | ✅ 완료 |
| Action 2개 이상 | ⬜ **경로당 Sheets 모듈 추가 필요** |
| 조건 분기 1개 이상 | ✅ Router 2경로 |
| 양쪽 경로 실제 실행 | ✅ 각 2회 실행 확인됨 |

---

## STEP 1. Make 보완 (5분)

- [ ] 시트에 `참석자` / `미참석자` 탭 2개 추가, 헤더 입력

  | A | B | C | D |
  |---|---|---|---|
  | 처리시각 | 이름 | 이메일 | 처리도구 |

- [ ] Make에서 **1st 경로 Gmail 모듈 우측 반원** 클릭 → `Google Sheets` → **Add a Row**
  - Sheet: `참석자`
  - 처리시각: `{{now}}`
  - 이름 / 이메일: 트리거 필드 매핑
  - 처리도구: `Make` (직접 입력)
- [ ] **2nd 경로**에도 동일하게 추가 (Sheet만 `미참석자`로)
- [ ] 저장 💾

> `처리도구` 열을 넣는 이유: 나중에 Zapier가 쓴 행과 섞이므로, 어느 도구가 처리했는지 구분됩니다.
> **캡처 한 장으로 두 도구의 실행 결과를 동시에 증명**할 수 있습니다.

## STEP 3. Zapier 구축 (30분) ← 여기가 남은 핵심

> ⚠️ **Zapier 무료 플랜은 2단계(Trigger + Action 1개)만 지원합니다.**
> 우리 구조는 Trigger + Filter + Action 2개 = 4단계라 **무료로는 불가능**합니다.
> 가입 시 제공되는 **14일 Professional 무료 체험**(결제정보 불필요)을 활성화하세요.
> 안 되면 → STEP 3-대안으로.

- [ ] [zapier.com](https://zapier.com) 가입
- [ ] 체험 플랜 활성화 확인

📸 `captures/zapier/00-플랜확인.png` — 보고서에서 "유료 기능 사용 사유"의 근거자료가 됩니다

### Zap A — 참석 확정

- [ ] **Create** → **Zaps**
- [ ] **Trigger**: `Google Sheets` → **New Spreadsheet Row**
  - 스프레드시트 / 워크시트: 응답 시트 선택
  - **Test trigger**로 샘플 행 확보
- [ ] `+` → **Filter**
  - 참석여부 필드 / **(Text) Exactly matches** / `참석` (실제 시트 값과 정확히 일치시킬 것)
- [ ] `+` → **Action**: `Gmail` → **Send Email**
  - Make에서 쓴 것과 **같은 문구**로 (동일 워크플로우 요건)
- [ ] `+` → **Action**: `Google Sheets` → **Create Spreadsheet Row**
  - Worksheet: `참석자` / 처리도구: `Zapier`
- [ ] **Publish**

📸 `captures/zapier/01-zapA.png`

### Zap B — 미참석

- [ ] Zap A **Duplicate** (⋯ 메뉴)
- [ ] Filter 조건 → `미참석` (또는 Does not exactly match `참석`)
- [ ] Gmail 문구 → 미참석 안내로
- [ ] Sheets → `미참석자` 시트로
- [ ] **Publish**

📸 `captures/zapier/02-zapB.png`

### 실행 및 캡처

- [ ] 응답 시트에 테스트 행 2건 추가 → Zapier 폴링 대기 (또는 편집화면에서 수동 테스트)
- [ ] 양쪽 Zap 실행 확인

📸 `captures/zapier/03-task-history.png`

### ★ 왜 Zap을 2개로 나누는가 — 보고서 핵심 논거

Make는 **Router 하나로 단일 시나리오 안에서 양방향 분기**를 처리합니다.
Zapier는 Zap 단위 관리 구조라 **경로마다 Zap을 분리**하게 됩니다.

→ 공통 로직 수정 시 **Make는 1곳, Zapier는 2곳**을 고쳐야 합니다.
→ 한쪽만 고치는 실수가 나기 쉽습니다.

**직접 만들어본 사람만 쓸 수 있는 비교 항목입니다. 보고서에 반드시 넣으세요.**

## STEP 3-대안. Zapier 체험이 안 될 경우

**n8n**으로 교체합니다. "서로 다른 2개 이상의 도구" 요건은 그대로 충족됩니다.

```bash
npx n8n
```
→ `http://localhost:5678` 접속
→ 노드: `Google Sheets Trigger` → `Switch` → `Gmail` + `Google Sheets`

오히려 **"상용 SaaS vs 오픈소스 자가호스팅"** 비교 축이 생겨 보고서가 더 좋아집니다.
이 경로로 가시면 알려주세요. 상세 가이드 다시 써드립니다.
