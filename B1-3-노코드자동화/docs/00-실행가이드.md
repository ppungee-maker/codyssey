# B1-3 실행 가이드 (현행화 — 2026.07.23)

> Make P1 시나리오는 **이미 구축 완료**. 이 문서는 남은 작업(P1 Zapier + P2 전체)만 다룹니다.
>
> ⚠️ **왜 이 문서가 "가이드"인가:** 크롬 원격 디버깅으로 자동화해서 대신 클릭해드리려 했으나,
> Chrome 136+ 보안 정책이 기본 프로필 디렉토리의 디버깅 포트를 막아 브라우저 자동화가 불가능합니다
> (`chrome-debug.sh` 실행 시 "포트가 열리지 않았습니다" 오류). 그래서 Make·Zapier UI 조작은
> **본인이 직접** 진행하시고, 저는 정확한 설정값·복붙용 텍스트를 여기 다 준비해뒀습니다.
> 진행하시다 막히면 그 자리에서 캡처+에러메시지 붙여주세요. 같이 봅니다.
>
> 🔑 **API 키 / 웹훅 URL은 저에게 주실 필요 없습니다.** Make 화면의 Connections/모듈 필드에
> 본인이 직접 입력하시면 됩니다. 저는 어느 필드에 뭘 넣을지만 알려드리면 충분해요.

## 확정된 워크플로우

```
[Trigger]  Google Sheets — Watch New Rows (참석 응답 시트)
    |
[Router]   참석 여부 판정
    |
    +-- 1st: 참석 확정 --> [Action 1] Gmail 발송 (참석 안내)
    |                      [Action 2] Sheets '참석자' 시트 기록
    |
    +-- 2nd: 미참석   --> [Action 1] Gmail 발송 (미참석 확인)
                          [Action 2] Sheets '미참석자' 시트 기록
```

| 요구사항 | 상태 |
|---|---|
| Trigger 1개 이상 | ✅ 완료 |
| Action 2개 이상 | ⬜ **경로당 Sheets 모듈 추가 필요** |
| 조건 분기 1개 이상 | ✅ Router 2경로 |
| 양쪽 경로 실제 실행 | ✅ 각 2회 실행 확인됨 |

  |---|---|---|---|
  | 처리시각 | 이름 | 이메일 | 처리도구 |

- [ ] **2nd 경로**에도 동일하게 추가 (Sheet만 `미참석자`로)

> `처리도구` 열을 넣는 이유: 나중에 Zapier가 쓴 행과 섞이므로, 어느 도구가 처리했는지 구분됩니다.

## STEP 3. Zapier 구축 (30분) ← 여기가 남은 핵심

> ⚠️ **Zapier 무료 플랜은 2단계(Trigger + Action 1개)만 지원합니다.**
> 우리 구조는 Trigger + Filter + Action 2개 = 4단계라 **무료로는 불가능**합니다.
> 가입 시 제공되는 **14일 Professional 무료 체험**(결제정보 불필요)을 활성화하세요.
> 안 되면 → STEP 3-대안으로.

- [ ] [zapier.com](https://zapier.com) 가입
- [ ] 체험 플랜 활성화 확인

📸 `captures/zapier/00-플랜확인.png` — 보고서에서 "유료 기능 사용 사유"의 근거자료가 됩니다

### Zap A — 참석 확정

- [ ] **Create** → **Zaps**
- [ ] **Trigger**: `Google Sheets` → **New Spreadsheet Row**
  - 스프레드시트 / 워크시트: 응답 시트 선택
  - **Test trigger**로 샘플 행 확보
- [ ] `+` → **Filter**
  - 참석여부 필드 / **(Text) Exactly matches** / `참석` (실제 시트 값과 정확히 일치시킬 것)
- [ ] `+` → **Action**: `Gmail` → **Send Email**
  - Make에서 쓴 것과 **같은 문구**로 (동일 워크플로우 요건)
- [ ] `+` → **Action**: `Google Sheets` → **Create Spreadsheet Row**
  - Worksheet: `참석자` / 처리도구: `Zapier`
- [ ] **Publish**

📸 `captures/zapier/01-zapA.png`

### Zap B — 미참석

- [ ] Zap A **Duplicate** (⋯ 메뉴)
- [ ] Filter 조건 → `미참석` (또는 Does not exactly match `참석`)
- [ ] Gmail 문구 → 미참석 안내로
- [ ] Sheets → `미참석자` 시트로
- [ ] **Publish**

📸 `captures/zapier/02-zapB.png`

### 실행 및 캡처

- [ ] 응답 시트에 테스트 행 2건 추가 → Zapier 폴링 대기 (또는 편집화면에서 수동 테스트)
- [ ] 양쪽 Zap 실행 확인

📸 `captures/zapier/03-task-history.png`

### ★ 왜 Zap을 2개로 나누는가 — 보고서 핵심 논거

Make는 **Router 하나로 단일 시나리오 안에서 양방향 분기**를 처리합니다.
Zapier는 Zap 단위 관리 구조라 **경로마다 Zap을 분리**하게 됩니다.

→ 공통 로직 수정 시 **Make는 1곳, Zapier는 2곳**을 고쳐야 합니다.
→ 한쪽만 고치는 실수가 나기 쉽습니다.

**직접 만들어본 사람만 쓸 수 있는 비교 항목입니다. 보고서에 반드시 넣으세요.**

## STEP 3-대안. Zapier 체험이 안 될 경우

**n8n**으로 교체합니다. "서로 다른 2개 이상의 도구" 요건은 그대로 충족됩니다.

```bash
npx n8n
```
→ `http://localhost:5678` 접속
→ 노드: `Google Sheets Trigger` → `Switch` → `Gmail` + `Google Sheets`

오히려 **"상용 SaaS vs 오픈소스 자가호스팅"** 비교 축이 생겨 보고서가 더 좋아집니다.
이 경로로 가시면 알려주세요. 상세 가이드 다시 써드립니다.

## STEP 4. 프로젝트2 구축 — 보너스1(AI)·2(실패알림/재시도) 포함 (60분)

> 설계는 `02-프로젝트2-설계문서.md`에 이미 다 있습니다. 여기서는 **Make 화면에서 클릭 순서**만 다룹니다.
> 새 시나리오(Make의 새 Scenario)로 만드세요. P1과 별개입니다.

### 4-0. 시트 3개 준비

기존 응답 시트와 무관한 **새 스프레드시트**(또는 새 탭)에 아래 3개 탭 + 헤더를 만드세요.

| 탭 | A | B | C | D | E |
|---|---|---|---|---|---|
| `중요메일` | 처리시각 | 제목 | 발신자 | 요약 | 카테고리 |
| `일반메일` | 처리시각 | 제목 | 발신자 | | |
| `처리실패` | 처리시각 | 제목 | 발신자 | 원본본문 | 오류메시지 |

### 4-1. Trigger — Gmail Watch Emails

- [ ] 새 Scenario 생성 → 첫 모듈 검색창에 `Gmail` → **Watch Emails**
- [ ] Folder: `INBOX`, Criteria: 기본값(전체), Max results: `5`, Mark seen emails: **Yes**
  (매번 같은 메일을 다시 안 읽도록. 안 켜면 중복 실행됨)
- [ ] **Run once**로 테스트 메일 1건 확보 (샘플 번들이 있어야 다음 모듈에서 필드 클릭 가능)

### 4-2. 분기 — Router

- [ ] Gmail 모듈 오른쪽 반원 클릭 → **Router** 추가 (2경로 생성됨)

**경로 1(중요) 필터** — Router 경로1 깔때기 아이콘 클릭:
- [ ] 조건 그룹, **Or** 로 묶어서:
  `Subject` **Contains** `계약` **OR** `Subject` **Contains** `긴급` **OR** `Subject` **Contains** `승인` **OR** `Subject` **Contains** `마감`

**경로 2(일반) 필터**:
- [ ] `Subject` **Does not contain** `계약`/`긴급`/`승인`/`마감` (경로1과 정확히 반대 조건 — Router의 "Fallback route"로 지정하면 더 간단합니다: 경로1에 조건 걸고 경로2는 Fallback으로 표시)

### 4-3. 경로1 — Claude API 호출 (보너스 1)

- [ ] 경로1 끝에 모듈 추가 → `HTTP` → **Make a request**
- [ ] URL: `https://api.anthropic.com/v1/messages`
- [ ] Method: `POST`
- [ ] Headers 3개 추가:
  | Name | Value |
  |---|---|
  | `x-api-key` | *(본인 API 키 직접 입력 — 저는 안 봐도 됩니다)* |
  | `anthropic-version` | `2023-06-01` |
  | `content-type` | `application/json` |
- [ ] Body type: **Raw**, Content type: `JSON (application/json)`
- [ ] Request content에 `02-프로젝트2-설계문서.md` 5절의 JSON 그대로 붙여넣기
  - ⚠️ `{{1.subject}}` `{{1.text}}` 부분은 **직접 타이핑하지 말고**, 커서를 그 자리에 두고
    오른쪽에 뜨는 Gmail 모듈(1번) 출력 필드 목록에서 **Subject**, **Text**를 클릭해서 넣으세요
    (모듈 번호가 자동으로 정확히 매핑됩니다)
- [ ] **Run once**로 테스트 → 응답 200 확인, `data.content` 배열이 오는지 확인

### 4-4. 경로1 후속 — Sheets 기록 + Discord 알림

- [ ] HTTP 모듈 뒤에 `Google Sheets` → **Add a Row**
  - Sheet: `중요메일`
  - 요약/카테고리 칸: HTTP 모듈 출력에서 `data → content[] → text` 를 클릭해 매핑
    (설계문서에 적었듯 Make 배열 인덱스는 **1부터**입니다. 자동 매핑 시 헷갈리지 말 것)
- [ ] 그 뒤에 `HTTP` → **Make a request** 하나 더 추가 (Discord 알림용)
  - URL: 본인이 만든 **Discord 웹훅 URL** 직접 입력
  - Method: `POST`, Body: Raw JSON
  - `{"content": "📩 중요메일 요약\n제목: {{1.subject}}\n{{요약필드}}"}`

### 4-5. 경로2 — 그냥 기록만

- [ ] 경로2 끝에 `Google Sheets` → **Add a Row** → Sheet: `일반메일` (제목/발신자만)

### 4-6. 에러 핸들러 — 재시도 + 실패알림 + 원본적재 (보너스 2)

- [ ] 4-3의 **Claude API HTTP 모듈**에 마우스 올리면 우하단에 뜨는 **빨간 원(⚠) 아이콘** 클릭
  → **Add error handler**
- [ ] 에러 핸들러 경로 안에 모듈 추가 → 검색 `Break`
  - Scheduling: Interval `15분`, Repeat: `3회`
  - (Break는 실패한 지점부터 시나리오 재실행을 자동 예약합니다 — 3회 다 실패하면 다음 모듈로 진행)
- [ ] Break 뒤에 `HTTP` → **Make a request** 추가 (Discord 실패알림)
  - Body: `{"content": "⚠️ 자동화 실패\n대상: {{1.subject}}\n단계: Claude API 호출\n오류: {{error.message}}"}`
- [ ] 그 뒤에 `Google Sheets` → **Add a Row** → Sheet: `처리실패` (제목/발신자/원본본문/오류메시지)

### 4-7. 실행 및 캡처

- [ ] 본인 메일함에 테스트 메일 2통 발송(자기 자신에게) — 1통은 제목에 `긴급` 포함(경로1), 1통은 일반 제목(경로2)
- [ ] Scenario **Run once**(또는 활성화 후 폴링 대기) → 양쪽 경로 실행 확인
- [ ] **보너스2 검증**: 4-3 HTTP 모듈의 `x-api-key` 값 끝에 아무 글자나 붙여 일부러 틀리게 만들기 →
      Run once → Discord 실패알림 도착 + `처리실패` 시트에 원본 적재 확인 → **키 원복하는 것 잊지 말 것**
