## 1. 사용한 도구

| 도구 | 버전/플랜 | 선정 이유 |
|---|---|---|
| **Make** | Free | 시각적 노드 기반의 대표 주자. 무료 플랜에서 Router를 제공해 분기 설계를 온전히 실습할 수 있음 |
| **Zapier** | Professional 14일 체험 | 시장 점유율이 가장 높은 자동화 SaaS. 순차 리스트 기반 UI로 Make와 대조적인 설계 철학을 가짐 |

### ⚠️ 유료 기능 사용에 대한 설명

과제 제약사항 *"유료 결제가 필요한 기능을 사용했다면 왜 불가피했는지와 무료 대안을 함께 정리한다"* 에 따라 기술한다.

**Zapier 무료 플랜으로는 본 과제의 요구사항을 충족할 수 없다.**

Zapier Free는 **2단계(Trigger + Action 1개) 워크플로우만** 지원한다. 그러나 본 과제의 공통 요구사항은 *Action 2개 이상 + 조건 분기 1개 이상*이므로, 최소 4단계(Trigger → Filter → Action → Action) 구성이 필요하다. 즉 무료 플랜에서는 **구조적으로 구현이 불가능**하다.

이에 따라 신규 가입 시 제공되는 **Professional 14일 무료 체험**(결제 정보 미요구)을 사용했다.

**무료 대안:** 동일 구조를 무료로 구현하려면 **n8n**(오픈소스, 자가호스팅 시 실행량 무제한) 또는 **Make 단독**을 사용해야 한다. 실제로 Make는 동일 워크플로우를 무료 플랜 내에서 완전히 구현할 수 있었다.

**→ 이 사실 자체가 두 도구의 가장 실질적인 차이다.**

## 2. 구현한 워크플로우

**업무 시나리오:** 행사 참석 여부 응답을 수집해, 참석/미참석에 따라 서로 다른 안내 메일을 자동 발송하고 명단을 분리 관리한다.

두 도구에 **동일한 구조**를 구현했다.

```
[Trigger]  Google Sheets — 응답 시트에 새 행 추가
    |
[분기]     참석 여부 판정
    |
    +-- 참석 확정 --> [Action 1] Gmail 참석 안내 메일 발송
    |                 [Action 2] '참석자' 시트에 기록
    |
    +-- 미참석   --> [Action 1] Gmail 미참석 확인 메일 발송
                      [Action 2] '미참석자' 시트에 기록
```

### Make 구현

| 단계 | 모듈 | 설정 |
|---|---|---|
| Trigger | Google Sheets — Watch New Rows | 응답 시트, 헤더 인식 On |
| 분기 | **Router** + 경로별 Filter | 1st `참석 확정` / 2nd `미참석` |
| Action 1 | Gmail — Send an email | 분기별 안내 문구 |
| Action 2 | Google Sheets — Add a Row | `참석자` / `미참석자` 시트 |

- 실행 방식: 15분 간격 폴링 (무료 플랜 최소 간격), 테스트는 Run once로 즉시 실행
- **단일 시나리오** 안에서 양방향 분기 완결
- 양쪽 경로 각 **2회** 실행 확인 (1st 참석 확정 2회 / 2nd 미참석 2회)

📎 캡처: `captures/make/01-전체시나리오.png`, `captures/make/02-실행이력.png`

### Zapier 구현

| 단계 | 모듈 | 설정 |
|---|---|---|
| Trigger | Google Sheets — New Spreadsheet Row | 응답 시트 |
| 분기 | **Filter by Zapier** | Zap A: `참석` / Zap B: `미참석` |
| Action 1 | Gmail — Send Email | Make와 동일 문구 |
| Action 2 | Google Sheets — Create Spreadsheet Row | `참석자` / `미참석자` 시트 |

- **Zap 2개로 분리 구현** — 아래 3장 ③항목에서 상술
- 실행 방식: 폴링 (플랜별 주기 상이)

📎 캡처: `captures/zapier/01-zapA.png`, `captures/zapier/02-zapB.png`

### ③ 조건 분기 구조 ★ 핵심 차이

| | Make | Zapier |
|---|---|---|
| 분기 방식 | Router 1개로 단일 시나리오 내 처리 | Zap 2개로 분리 |
| 무료 플랜 지원 | ✅ Router/Filter 포함 | ❌ 2단계 제한으로 실질 불가 |
| 공통 로직 수정 시 | **1곳** 수정 | **2곳** 수정 |

**이것이 실무에서 가장 크게 체감되는 차이다.** 알림 문구 하나를 바꾸려 해도 Zapier에서는 두 Zap을 각각 열어 동일한 수정을 반복해야 했고, 이 과정에서 한쪽만 수정하는 실수가 발생하기 쉽다. 반면 Make는 Router 이전 단계를 고치면 양쪽에 일괄 반영된다.

### ④ 무료 플랜 범위

| | Make Free | Zapier Free |
|---|---|---|
| 월 실행량 | 1,000 credits | 100 tasks |
| 워크플로우 깊이 | 제한 없음 | **2단계까지만** |
| 활성 시나리오/Zap | 2개 | — |
| 최소 실행 간격 | 15분 | — |
| 분기 기능 | Router/Filter 포함 | Filter 포함(단 깊이 제한에 걸림) |

*출처: 2026년 7월 기준 make.com/pricing, zapier.com/pricing*

**결론:** 학습·소규모 개인 자동화 목적이라면 무료 범위만 놓고 봐도 Make의 실용성이 압도적이다.

### ⑤ 연동 서비스 범위

| | Make | Zapier |
|---|---|---|
| 공식 연동 앱 수 | 3,000+ | 8,000+ |
| 커스텀 HTTP 요청 | HTTP 모듈 (무료) | Webhooks by Zapier (유료 플랜) |

**Zapier가 커넥터 수에서는 앞선다.** 다만 커넥터 수와 실제 접근성은 별개다. **Make는 HTTP 모듈을 무료 플랜에 포함하는 반면 Zapier는 Webhooks를 유료 기능으로 묶어두었다.** 즉 공식 커넥터가 없는 서비스를 직접 연동해야 하는 상황에서는, 앱 수가 적은 Make 쪽이 오히려 무료로 해결 가능하다.

## 4. 각 도구의 장단점

### Make

**장점**
- 무료 플랜에서 Router·Filter·HTTP를 모두 제공해 **무료만으로 완결된 워크플로우 구현 가능**
- 시각적 노드 구조로 복잡한 분기의 전체 흐름 파악이 쉬움
- 실행 로그에서 각 모듈의 입출력 데이터를 상세히 확인 가능
- `___`

**단점**
- 변수 참조 문법 등 초기 학습 곡선 존재
- 무료 플랜 최소 실행 간격 15분 — 즉시성이 필요한 자동화에는 부적합
- 활성 시나리오 2개 제한
- `___`

### Zapier

**장점**
- 단계별 드롭다운 위주로 진입 장벽이 낮음
- 연동 앱 수가 가장 많아 원하는 서비스를 찾을 확률이 높음
- 순차 구조라 단순한 워크플로우는 오히려 읽기 쉬움
- `___`

**단점**
- **무료 플랜이 2단계로 제한돼 실질적인 자동화 구현이 어려움**
- 분기마다 Zap을 분리하게 되어 유지보수 비용 증가
- Webhooks 등 기본적인 기능이 유료 플랜에 묶여 있음
- `___`

| 상황 | 추천 | 근거 |
|---|---|---|
| 개인 학습 / 비용 0원 | **Make** | 무료 플랜만으로 분기 포함 워크플로우 완결 가능 |
