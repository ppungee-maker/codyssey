# 리포 폴더 관리 컨벤션

이 문서가 이 리포의 "어디에 뭘 두는지" 표준이다. 새 폴더/파일을 리포 루트에 만들기
전에 먼저 여기서 맞는 자리를 찾는다 — 맞는 게 없으면 이 문서에 새 규칙을 추가하고 쓴다.

## 최상위 레이아웃

```
codyssey/
├── src/codyssey/     # QA 자동화 + naeto/precheck 파이썬 패키지 (코드)
├── docs/             # 레퍼런스 문서 — API 엔드포인트, 사이트 사용법, 이 문서 같은 컨벤션
├── missions/         # 코디세이 학습 미션 예시답안/산출물 (미션당 폴더 1개, 아래 참고)
├── qa-reports/        # (gitignored) codyssey map/mission 등이 만드는 QA 리포트
├── screenshots/       # (gitignored) QA 자동화가 찍는 화면 캡처
├── media/             # (gitignored) naeto image/tts/video 생성물 기본 저장 위치
└── (설정 파일들: pyproject.toml, .env, chrome-debug.sh, README.md 등)
```

**원칙**: 리포 루트에는 위 6개 카테고리 + 설정 파일만 둔다. 미션 답안이든 뭐든 새
산출물 종류가 생겨도 루트에 새 최상위 폴더를 함부로 추가하지 말고, 이미 있는 카테고리
(`missions/`, `docs/` 등) 아래에 넣을 자리부터 찾는다.

> 왜 `missions/`가 따로 있나: 예전엔 `B1-3-노코드자동화/`처럼 미션 폴더가 리포 루트에
> 바로 있었다. 미션이 하나둘 늘면 루트가 미션 폴더로 덮여서 `src/`·`docs/` 같은 진짜
> 코드/문서 폴더를 찾기 어려워진다 — 그래서 전부 `missions/` 아래로 모은다.

## `missions/` 내부 컨벤션 (미션 답안 폴더 1개당)

`B1-3-노코드자동화/`(현재는 git 히스토리에만 존재)에서 확립되고, `B2-1-...`에서
그대로 이어받은 패턴:

```
missions/B{미션번호}-<제목압축(공백없이)>/
├── docs/
│   ├── 00-실행가이드.md         # STEP 체크리스트 (자동화 안 되는 수동 단계 지시 포함)
│   ├── 01-<필수산출물>.md       # 미션이 요구하는 문서형 산출물 (번호는 요구사항 등장 순)
│   ├── 02-...                   # 산출물이 여러 개면 계속 번호를 늘림
│   └── 모범답안-B{미션번호}.md   # 요구사항 충족 매핑 셀프체크 표 + 개요 (번호 없음,
│                                  이 폴더의 README 역할 — 별도 README.md는 안 둠)
├── images/ 또는 그 미션에 맞는 산출물 폴더  # 문서가 아닌 실제 산출물 파일
│   ├── final/                   # 제출용 최종본
│   └── drafts/                  # 초안(작업로그가 참조하는 비교 근거)
├── bonus/<보너스명>/            # 보너스 과제 산출물 (있으면)
└── captures/<도구명>/NN-설명.png  # 자동화 불가/수동 진행 과정의 증빙 캡처
```

규칙:
- 폴더명은 `B{n}-<제목을 압축한 한글, 공백 없이>` (예: `B1-3-노코드자동화`, `B2-1-AI기반UIUX디자인시안제작`).
- `docs/00-`는 항상 실행가이드, `01-`부터는 미션이 실제로 요구하는 산출물 문서에 번호를 붙인다.
- `모범답안-B{n}.md`는 번호 없이 미션 ID를 파일명에 직접 박는다 — 이 폴더에 들어온 사람이
  제일 먼저 볼 문서(사실상 이 폴더의 README) 역할.
- 실제 생성 파일(이미지/코드 등)은 `docs/` 밖에, 성격에 맞는 이름의 폴더에 둔다.
  초안↔최종본이 구분되는 산출물이면 `final/`·`drafts/`로 나눈다.
- 사람이 직접 해야 하는 단계(Figma 조작, 브라우저 자동화가 막힌 도구 등)의 증빙은
  `captures/<도구명>/`에 번호+설명 파일명으로.

## 자동화 산출물(gitignored) vs 커밋되는 산출물

- `screenshots/`, `qa-reports/`, `media/`(기본 naeto 출력 경로)는 **로컬 QA/생성 산출물**이라
  `.gitignore` 처리됨 — 커밋 안 됨, 매번 새로 생성 가능.
- `missions/*/images/`처럼 **미션 답안 자체의 산출물**은 커밋 대상이므로, naeto로 생성할 때
  `out_dir`를 `media/`(기본값) 대신 미션 폴더 안의 경로로 **반드시 오버라이드**해야 한다.
