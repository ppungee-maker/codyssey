# 프롬프트 템플릿 — 플랫폼별 콘텐츠 생성

필수 산출물 ③. 주제: **"친환경 텀블러 신제품 출시"** (미션 예시 프롬프트와 결이 같은
주제로 채택 — `naeto-seai-usage.md` 레퍼런스 문서의 이미지 예시 "친환경 텀블러
제품샷"과도 자연스럽게 이어짐).

> ⚠️ **상태**: 2026-07-25 기준 `naeto chat`이 서버 오류(모든 프리셋·모델에서
> `event:error` — 서비스 전반 장애로 판단, `naeto image`는 별도 프로바이더라 정상)로
> 아래 프롬프트의 **실제 생성 결과 확인이 아직 안 됨**. 프롬프트 설계와 각 결정의
> 이유는 확정, "수정 과정(초안→최종)"은 서비스 복구 후 실제 응답을 보고 채운다.
> 이미지 프롬프트는 `naeto image`가 살아있어서 실제로 생성·검증 완료.

## 공통 입력

```
주제: 친환경 텀블러 신제품 출시
톤: 기본(중립) — 보너스 A/B에서 친근한/전문적인 두 버전으로 분기
```

## 1. 인스타그램 — 캡션 + 해시태그

**설계 기준**: 미션 예시 "짧은 캡션 + 해시태그 10개 내외"를 그대로 채택. 인스타그램은
스크롤 속도가 빨라 첫 줄에서 훅(hook)이 있어야 한다고 판단해 프롬프트에 명시.

```
다음 주제로 인스타그램 게시글 캡션을 써줘.

주제: {topic}

조건:
- 첫 줄은 짧고 강한 훅(hook) 문장으로 시작
- 전체 3~4문장, 이모지 2~3개 자연스럽게 포함
- 마지막 줄에 관련 해시태그 10개 내외 (한글+영문 섞어서)
- 존댓말이지만 친근한 구어체
```

## 2. 블로그 — 본문 + 소제목 구조

**설계 기준**: 미션 예시 "500자 이상 본문 + 소제목 구조"를 그대로 채택. 소제목 개수를
"2~3개"로 못박은 이유는 너무 잘게 쪼개면 블로그 특유의 서술형 흐름이 깨지기 때문.

```
다음 주제로 블로그 게시글 본문을 써줘.

주제: {topic}

조건:
- 전체 500자 이상
- 소제목(##) 2~3개로 구조화 (예: 도입/특징/구매 정보)
- 정보 전달 위주, 과장된 마케팅 문구는 지양
- 문단 끝에 자연스러운 다음 문단 연결
```

## 3. X(구 트위터) — 280자 이내 요약

**설계 기준**: 글자수 제한이 명시적이라 프롬프트에도 숫자를 그대로 못박았다.
해시태그를 인스타그램만큼 넣지 않은 이유: X는 해시태그 과다 사용 시 오히려
가독성이 떨어진다는 통념을 반영해 1~2개로 제한.

```
다음 주제로 X(트위터) 게시글을 써줘.

주제: {topic}

조건:
- 전체 280자 이내 (공백 포함)
- 핵심 정보 1~2가지만 담기
- 해시태그 1~2개만
- 간결하고 담백한 톤
```

## 6. 남은 작업

1. `naeto chat` 복구되면 §1~3 프롬프트로 실제 텍스트 생성 → 결과 검토 → 필요시
   문구 수정(초안→최종 과정을 여기 추가 기록) → 최종 확정.
2. 보너스1 텍스트 A/B 버전 생성 후 `02-README.md`에 비교 결론 작성.
