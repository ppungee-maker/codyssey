# M1-2 AI Agent 개발: 나만의 AI 비서 구축 — 모범답안

`AI 응용 학습 (AI Native Master)` 과정 미션. 시계열 데이터를 저장·요약하고, AI가
그 요약을 컨텍스트로 받아 대화하는 풀스택 서비스.

## 설계 결정: 왜 "코드 완성 + 배포 가이드" 스코프인가

이 미션은 A2/M1-1 시리즈와 달리 **외부 실 계정 3종**(Firebase, OpenAI 유료 키,
Render+Vercel)이 배포 요구사항에 명시적으로 걸려 있다 — mock으로 대체해도 되는
"생성 결과물 품질" 문제가 아니라, 애초에 계정이 없으면 배포 자체가 불가능하다.
제니형님과 상의해 "코드는 완전히 완성하고 배포는 형님이 직접 진행 — 그대로 따라
하면 되는 가이드 문서를 남긴다"로 스코프를 정했다.

대신 **배포 없이도 코드가 실제로 동작한다는 걸 증명**하기 위해, A2 시리즈에서
검증된 provider 패턴을 storage/AI 두 계층에 그대로 적용했다:

- `backend/app/storage/` — `Store` 인터페이스, `MemoryStore`(로컬 기본값)와
  `FirestoreStore`(배포용) 두 구현체. `FIREBASE_CREDENTIALS_JSON` 유무로 자동 전환.
- `backend/app/ai/` — `LLMProvider` 인터페이스, `MockLLMProvider`(로컬 기본값)와
  `OpenAILLMProvider`(배포용). `OPENAI_API_KEY` 유무로 자동 전환.

덕분에 로컬에서 백엔드+프론트엔드를 실제로 띄우고 Playwright로 전체 플로우(데이터
CRUD, 요약, 챗봇 컨텍스트 주입, 대화 저장/불러오기)를 직접 조작해 검증했다 —
`captures/local-run/` 6장이 그 증거다. mock LLM도 고정 문자열이 아니라 시스템
프롬프트에 주입된 실제 데이터 요약(건수/평균/추세)을 파싱해 반영하므로, "컨텍스트
주입이 실제로 연결돼 있는지"까지 검증 가능하다.

|---|---|---|
| 1 | 개발환경(FastAPI/uvicorn/firebase-admin/openai/dotenv), Firebase/OpenAI 준비 | `backend/requirements.txt`, `backend/app/config.py` (`_load_dotenv`) |
| 2 | 데이터 선정(100+포인트), 요약정보(기간/개수/통계/추세) | M1-1의 NVDA 502건 재사용(`seed_nvda_daily.csv`) — `routers/data.py::get_summary` |

| 4 | Firestore, 서비스계정키 env 관리, 컬렉션구조(data/conversations) | `storage/firestore_store.py`(구현 완료, 로컬 검증은 `MemoryStore`로 대체 — 인터페이스 동일) |

| 7 | AI 챗봇 API(컨텍스트 주입: 요약조회→시스템프롬프트삽입→GPT호출→자동저장) | `routers/chat.py::build_system_prompt` + `chat()` |

| 10 | 프론트 배포(Vercel), README(소개/스택/URL/실행법/env/스크린샷) | [`01-배포가이드.md`](01-배포가이드.md) §4 (미배포), [`../README.md`](../README.md)(README 요구 항목 전부 포함, URL은 배포 후 채울 자리로 명시) |
