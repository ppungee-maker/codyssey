# M1-2 배포 가이드 (Render + Vercel)

코드는 완성돼 있고 로컬에서(`captures/local-run/`) 전체 플로우를 검증했다. 이
문서는 **실제 배포를 진행할 때** 그대로 따라 하면 되는 단계별 가이드다 — Firebase/
OpenAI/Render/Vercel 계정이 필요해서 이 세션에서는 진행하지 않았다.

## 0. 준비물 체크리스트

- [ ] Firebase 프로젝트 (Firestore 활성화)
- [ ] Firebase 서비스 계정 키 (JSON)
- [ ] OpenAI API 키
- [ ] GitHub 저장소 (이 코드가 push된 상태)
- [ ] Render 계정 (백엔드용, 무료 티어 가능)
- [ ] Vercel 계정 (프론트엔드용, 무료 티어 가능)

## 1. Firebase 프로젝트 생성

1. [Firebase 콘솔](https://console.firebase.google.com) → "프로젝트 추가"
2. 왼쪽 메뉴 "Firestore Database" → "데이터베이스 만들기" → 프로덕션 모드(또는 테스트
   모드로 시작 후 나중에 보안 규칙 강화) → 리전은 `asia-northeast3`(서울) 권장
3. "프로젝트 설정"(톱니바퀴) → "서비스 계정" 탭 → "새 비공개 키 생성" → JSON 파일
   다운로드. **이 파일은 절대 GitHub에 커밋하지 않는다** — 3-3 단계에서 내용을
   그대로 Render 환경변수에 붙여넣는다.

## 2. OpenAI API 키 준비

[platform.openai.com](https://platform.openai.com/api-keys)에서 키 발급. 과금이
걱정되면 사용량 한도(Usage limits)를 낮게 설정해두는 것을 권장한다.

## 3. 백엔드 배포 (Render)

### 3-1. GitHub에 push

이 레포(`backend/` 포함)가 이미 GitHub에 있다면 이 단계는 생략.

### 3-2. Render Web Service 생성

1. [Render 대시보드](https://dashboard.render.com) → "New" → "Web Service"
2. GitHub 레포 연결, 아래처럼 설정:

| 항목 | 값 |
|---|---|
| Root Directory | `backend` (이 미션 폴더 기준 하위 경로 — 레포 루트가 다르면 실제 경로에 맞게 조정) |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| Instance Type | Free 로 시작 가능 |

### 3-3. 환경변수 설정 (Render → Environment)

| 키 | 값 |
|---|---|
| `OPENAI_API_KEY` | 2단계에서 발급받은 키 |
| `OPENAI_MODEL` | `gpt-4o-mini` (비용 절감, 필요시 변경) |
| `FIREBASE_CREDENTIALS_JSON` | 1단계 JSON 파일의 **전체 내용을 한 줄로** 붙여넣기 (JSON을 압축해 한 줄로 만들려면 `python -c "import json;print(json.dumps(json.load(open('key.json'))))" ` 실행 후 출력을 복사) |
| `FIREBASE_PROJECT_ID` | Firebase 프로젝트 ID |
| `CORS_ORIGINS` | 4단계에서 나올 Vercel URL (예: `https://your-app.vercel.app`) — Vercel 배포 후 다시 와서 채운다 |

추가로 `requirements.txt`의 주석 처리된 `openai`, `firebase-admin`을 주석 해제해야
한다(로컬 개발 기본값은 mock/memory라 두 패키지가 없어도 동작하지만, 배포 시엔
실제로 import되므로 필요).

### 3-4. 배포 확인

배포가 끝나면 `https://<서비스명>.onrender.com/docs`에서 Swagger UI가 뜨는지 확인.
`https://<서비스명>.onrender.com/`(health check)의 `storage`/`ai_provider` 값이
각각 `firestore`/`openai`로 나오면 실제 서비스로 정상 전환된 것이다.

⚠️ **무료 티어 콜드스타트**: Render 무료 인스턴스는 일정 시간 요청이 없으면
슬립 상태가 되고, 첫 요청에 30초 이상 걸릴 수 있다. 프론트엔드에 "첫 응답이
느릴 수 있습니다" 안내 문구를 두거나, 로딩 표시(이미 구현됨)로 충분히 대응된다.

## 4. 프론트엔드 배포 (Vercel)

### 4-1. `config.js` 수정

`frontend/config.js`의 `API_BASE_URL`을 3-4에서 확인한 Render URL로 바꾼다.

```js
const API_BASE_URL = "https://<서비스명>.onrender.com";
```

빌드 스텝이 없는 순수 정적 파일이라 이 값을 직접 고치고 다시 push하는 게 가장
단순하다(환경변수 기반 빌드 치환은 이 규모의 바닐라 프로젝트엔 과함).

### 4-2. Vercel 프로젝트 생성

1. [Vercel 대시보드](https://vercel.com/new) → GitHub 레포 Import
2. Root Directory를 `frontend`로 지정
3. Framework Preset은 "Other"(정적 파일, 빌드 불필요)
4. Deploy

### 4-3. CORS 마무리

배포된 Vercel URL(`https://your-app.vercel.app`)을 Render의 `CORS_ORIGINS`
환경변수에 추가하고 Render 서비스를 재배포(Manual Deploy)한다 — 안 하면 브라우저가
CORS 에러로 API 호출을 막는다.

## 5. 최종 점검 체크리스트 (README 제출 스크린샷과 동일)

- [ ] Vercel URL 접속 → 데이터 요약이 뜬다(Firestore 연결 확인)
- [ ] 채팅으로 질문 → GPT가 실제 자연어로 답한다(mock이 아니라 `provider: "openai"` 확인)
- [ ] 데이터 추가/삭제 중 최소 1개가 화면에서 확인된다
- [ ] 대화 목록에서 이전 대화를 불러올 수 있다
- [ ] `<render-url>/docs`에서 Swagger UI가 뜬다
