# B2-2 실행 가이드

> **왜 이 미션은 대부분 형님이 직접 하셔야 하나**: B2-1(이미지 생성)과 달리 이 미션은
> **실제 살아있는 자동화 워크플로우**(Make 등)와 **Notion 워크스페이스**가 있어야
> 완성됩니다. 둘 다 형님 개인 계정이 필요해서(가입·로그인·OAuth 동의) 저는 대신 만들 수
> 없어요 — B1-3 때와 같은 이유입니다. 대신 정확한 모듈 구성·설정값·프롬프트를 전부
> 준비해뒀으니 클릭만 따라오시면 됩니다.
>
> **왜 naeto가 아니라 Claude/OpenAI API인가**: `naeto`는 코디세이 로그인 세션 쿠키로
> 인증하는 이 리포 전용 도구라 Make 같은 외부 서비스에서 재사용할 수 없습니다(세션
> 쿠키를 Make에 심는 건 불가능/비정상). 그래서 **실제 Make 시나리오는 Claude 또는
> OpenAI API(개인 API 키)**를 쓰도록 설계했고, `naeto chat`은 그 프롬프트가 실제로
> 잘 작동하는지 **미리 검증**하는 용도로만 썼습니다(현재 naeto chat이 일시적으로
> 서버 오류라 검증은 나중에 채워넣습니다 — [`02-프롬프트검증.md`](02-프롬프트검증.md) 참고).

## STEP 0. 준비물

- [ ] Make 계정 (무료 플랜으로 충분 — 하루 1회 스케줄, 저볼륨)
- [ ] Notion 계정 + 새 워크스페이스(또는 기존 워크스페이스에 새 페이지)
- [ ] Claude 또는 OpenAI API 키 (요약 1건당 짧은 호출이라 비용 미미)
- [ ] RSS 피드 URL 1개 — 기술 뉴스 소스. 예시로 검증한 피드: `https://techcrunch.com/feed/`
  (다른 소스를 원하면 아무 RSS/Atom 피드 URL이나 가능)

## STEP 1. Notion 데이터베이스 만들기

1. [ ] Notion에서 새 페이지 → **데이터베이스(Table)** 생성, 이름 예: `뉴스 요약 자동화`
2. [ ] 속성(컬럼) 4개 추가 (타입 정확히 맞출 것 — Make 매핑에 필요):
   | 속성명 | 타입 |
   |---|---|
   | 제목 | Title (기본 제공되는 Name 속성을 이 이름으로 변경해도 됨) |
   | 요약문 | Text |
   | 원문 링크 | URL |
   | 발행일시 | Date |
3. [ ] (중복 방지용) `원문 링크`를 Notion 쪽에서 **고유값 제약**으로 걸 수는 없으므로,
   중복 체크는 STEP 3의 Make 쪽 Router에서 처리한다(아래).
4. [ ] Make와 연동하려면: 데이터베이스 페이지 우측 상단 `···` → **Connections** → Make 앱 연결
   (또는 Make에서 Notion 모듈 추가 시 뜨는 OAuth 창에서 이 데이터베이스에 접근 허용).

## STEP 2. Make 시나리오 — Trigger + 데이터 수집

1. [ ] Make에서 새 Scenario 생성, 첫 모듈 검색 → **RSS** → **Watch RSS feed items**
   - Feed URL: 위에서 정한 RSS 피드 URL
   - Maximum number of results: `5` (한 번에 너무 많이 안 가져오게)
   - **Scheduling**(모듈 아래 시계 아이콘) → Every day, 원하는 시간(예: 매일 09:00) —
     이게 "매일 설정된 시간에 자동 실행" 요구사항을 충족한다.
2. [ ] **Run once**로 테스트 실행 → 샘플 항목이 잡히는지 확인.

## STEP 3. 주제 필터링 + 중복 방지 (Router)

1. [ ] RSS 모듈 뒤에 **Router** 추가 (경로 2개: "처리" / "스킵").
2. [ ] **경로 1(처리)** 필터 — 이 두 조건을 **AND**로:
   - `Title` **Contains** 원하는 키워드(예: `AI`) — 주제 필터링
   - **중복 방지**: 경로 1 앞에 `Notion` → **Search Objects** 모듈을 하나 더 넣어서
     `원문 링크` = 현재 항목의 `link`인 페이지가 있는지 조회 → 그 검색 결과 개수가
     `0`일 때만 통과하도록 필터 조건 추가(`Total number of bundles = 0`).
     → 이게 "동일 기사 중복 저장 방지"(원문 링크를 dedup 키로 사용) 요구사항이다.
3. [ ] **경로 2(스킵)**는 Router의 **Fallback route**로 지정(경로 1 조건에 안 걸리면
   자동으로 이쪽, 별도 모듈 없이 그냥 끝냄).

## STEP 4. AI 요약 (경로 1 안에)

1. [ ] 경로 1 끝에 `HTTP` → **Make a request** 추가.
2. [ ] URL: `https://api.anthropic.com/v1/messages` (OpenAI를 쓰려면
   `https://api.openai.com/v1/chat/completions`로 대체 — 아래 Body도 그에 맞게 변경)
3. [ ] Method: `POST`
4. [ ] Headers:
   | Name | Value |
   |---|---|
   | `x-api-key` | *(본인 API 키 직접 입력)* |
   | `anthropic-version` | `2023-06-01` |
   | `content-type` | `application/json` |
5. [ ] Body type: **Raw**, JSON:
   ```json
   {
     "model": "claude-haiku-4-5",
     "max_tokens": 200,
     "messages": [
       {"role": "user", "content": "다음 뉴스 기사를 한국어로 3줄 이내로 요약해줘. 각 줄은 핵심 사실 하나씩만 담고, 불필요한 수식어는 빼줘.\n\n제목: {{1.title}}\n본문: {{1.description}}"}
     ]
   }
   ```
   `{{1.title}}`/`{{1.description}}`은 직접 타이핑하지 말고 RSS 모듈(1번) 출력 필드
   목록에서 클릭해서 넣을 것 — 이 정확한 프롬프트는 [`02-프롬프트검증.md`](02-프롬프트검증.md)에서
   검증한 문구다.
6. [ ] **재시도 상한**: 이 HTTP 모듈에 에러 핸들러 추가(마우스 올리면 뜨는 ⚠ 아이콘) →
   **Break**, Interval `1분`, Repeat `2회` — "재시도는 최대 2회" 요구사항. Break 뒤에는
   STEP 6의 실패 처리로 연결한다.

## STEP 5. Notion에 저장

1. [ ] AI 요약 HTTP 모듈 뒤에 `Notion` → **Create a Database Item**.
2. [ ] 데이터베이스: STEP 1에서 만든 것 선택.
3. [ ] 속성 매핑:
   | Notion 속성 | 값 |
   |---|---|
   | 제목 | RSS 모듈의 `title` |
   | 요약문 | HTTP 응답의 `content[1].text`(Claude 응답 파싱 — Anthropic 응답은 배열 인덱스 1부터, 설계문서 참고) |
   | 원문 링크 | RSS 모듈의 `link` |
   | 발행일시 | RSS 모듈의 `pubDate` |

## STEP 6. 안정성 — 실패 처리

1. [ ] STEP 4의 Break 에러 핸들러 뒤에 `Notion` → **Create a Database Item** 하나 더
   (실패 로그용, 또는 별도 "처리실패" 데이터베이스를 만들어도 됨) — 제목/링크/에러메시지 기록.
2. [ ] (선택) 실패 알림용 Discord/Slack Webhook 모듈을 Break 뒤에 추가해도 좋다(B1-3 패턴 재사용).
3. [ ] RSS 피드 자체가 비어있는 경우(항목 0개)는 Router 조건에서 자연히 아무 것도
   처리되지 않고 끝난다 — 별도 에러가 아니라 정상 종료로 취급.
